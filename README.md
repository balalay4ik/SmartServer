# SmartServer

SmartServer — серверная система для управления и взаимодействия с IoT-устройствами.

Проект задуман как универсальная серверная часть, которая принимает данные от подключённых устройств, хранит их состояние и предоставляет механизмы для обмена командами и событиями.

Сейчас в качестве основного транспорта используется **MQTT**, а основным тестовым устройством является **ESP32**.

## О проекте

SmartServer выступает центральным узлом между IoT-устройствами и серверной логикой.

Устройство подключается к сети и устанавливает связь с сервером. Сервер принимает сообщения от устройств, обрабатывает их и при необходимости отправляет команды обратно.

На текущем этапе реализован сценарий с ESP32, который:

* подключается к Wi-Fi;
* использует собственный MQTT-клиент;
* обменивается с сервером данными в JSON;
* получает команды от сервера;
* передаёт команды контроллеру устройства.

В качестве физического прототипа используется ESP32 с подключённой силовой схемой управления небольшим мотором.

MQTT используется как текущий транспорт взаимодействия, но предметная область проекта не ограничивается исключительно MQTT.

## Архитектура

Проект разделён на несколько частей:

                                  │

### Host

`HomeServer.Host` — точка запуска приложения.

Host собирает необходимые зависимости, подключает модули и запускает HTTP API. При запуске также выполняются миграции базы данных и инициализируется MQTT.

### Core

`HomeServer.Core` содержит общие для системы абстракции и инфраструктурные компоненты, которые не относятся к конкретному типу устройства.

В Core также находится механизм ожидания событий по ключу (`EventWaiter<TKey, TValue>`). Он используется, например, в сценариях, где сервер должен дождаться ответа от конкретного устройства.

### MQTT

`HomeServer.Mqtt` отвечает за взаимодействие с MQTT.

Помимо самого подключения к брокеру, здесь реализована маршрутизация сообщений:

* MQTT handlers объявляются как отдельные классы;
* маршруты задаются атрибутами;
* параметры могут извлекаться непосредственно из MQTT topic;
* соответствующий handler находится через DI;
* входящее сообщение передаётся в найденный метод.

Таким образом, MQTT-обработка не привязана к одному большому обработчику сообщений, а разделена на отдельные маршруты.

### Devices

`HomeServer.Modules.Devices` — основной реализованный модуль проекта на текущем этапе.

Он отвечает за работу с IoT-устройствами и содержит логику, связанную с их регистрацией, состоянием и взаимодействием с ними.

### Persistence

`HomeServer.Persistence` отвечает за хранение данных.

Сейчас используется **SQLite**. В базе хранятся данные, связанные с зарегистрированными устройствами и журналированием работы системы.

Миграции базы данных применяются автоматически при запуске сервера.

### SDK

`HomeServer.SDK` содержит общие контракты, которые могут использоваться внешними компонентами и клиентами проекта.

В частности, это позволяет отделять протокол взаимодействия от конкретной реализации серверной части.

### Остальные модули

В структуре проекта также присутствуют отдельные модули для будущего расширения:

* `HomeServer.Modules.Automation`
* `HomeServer.Modules.Geo`
* `HomeServer.Modules.NAS`
* `HomeServer.Identity`

Они подготовлены как отдельные части архитектуры, но основная рабочая функциональность сейчас сосредоточена в модуле `Devices`.

## HTTP API

Помимо MQTT, сервер предоставляет HTTP API на базе ASP.NET Core.

HTTP используется как отдельный интерфейс взаимодействия с сервером и уже имеет рабочую структуру контроллеров, однако API продолжает развиваться.

## Запуск

Для запуска MQTT-брокера используется Docker Compose.

```bash
docker compose up -d
```

После этого запускается сервер:

```bash
dotnet run --project src/Host/HomeServer.Host
```

По умолчанию Mosquitto используется на стандартном MQTT-порту:

```text
1883
```

При запуске SmartServer самостоятельно выполняет необходимые миграции SQLite и инициализирует MQTT-сервис.

## Текущее состояние

На данный момент основной рабочий сценарий проекта — взаимодействие сервера с IoT-устройствами через MQTT.

В первую очередь развивается модуль `Devices` и инфраструктура, необходимая для подключения реальных устройств.
